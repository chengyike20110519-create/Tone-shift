# Tone-Shift 项目完整介绍

---

## 第一部分：项目起源与理念

### 1.1 我们是怎么想到这个点子的

这个产品的起点，来自一个所有人都经历过、但从未被解决的问题。

**场景一：深夜听歌**

你在深夜戴上耳机，播放一首《好想好想你》。音乐响起的瞬间，某种情绪涌上来——不是开心也不是难过，是一种模糊的、堵在胸口的东西。你想表达，但不知道该怎么说。

你打开朋友圈，打了几个字，删了。又打了几个字，又删了。

最后你锁了屏，那个感觉，跟着你一起睡了。

**场景二：同一首歌，不同的人**

你和一个朋友聊起同一首歌。你说这首歌好悲伤，他说"不会啊，我觉得很温暖"。你们争论了几句，发现谁也没法说服谁。

但你心里隐隐觉得：他怎么会听出温暖呢？他是不是没认真听？

后来你才知道——他听这首歌的时候正在恋爱，而你听的时候刚刚失恋。

**场景三：一首想不起名字的歌**

你脑子里一直在循环一段旋律，你知道那首歌对你很重要，但你就是想不起名字。你哼给朋友听，他说"没听过"。你在音乐App里搜歌词，只记得一两个词，搜不到。

那首歌像一块石头，一直压在你心里。

**场景四：音乐社交的尴尬**

你分享了一首歌到朋友圈，配文"太好听了"。没人点赞，没人评论。你也不知道该说什么——总不能写"这首歌让我想起了我前任"吧？

你把那条删了。

**这些场景指向同一个问题：**

音乐是情绪含量最高的媒介之一，但我们在音乐App里留下的，却是最没有情绪的东西——播放记录、歌名、时长、次数。

我们的情绪，听完歌就消失了。

### 1.2 我们发现了什么

**核心洞察一：情绪需要被看见，而不是被分析**

很多人误以为"情绪记录"="情绪分析"——像性格测试那样给你贴个标签。但我们发现，用户最抗拒的就是"被分析"。

用户不想被AI告诉自己"你很悲伤"——因为只有他自己知道，那一刻的悲伤里还掺杂着愤怒、不甘、或某种说不清的释然。

AI不可能知道。它只能瞎猜。

所以我们的原则是：**不分析，只记录。**

**核心洞察二：非语言表达比语言更诚实**

当人们被要求"描述你的情绪"时，大脑会启动防御机制——你会美化、修饰、甚至撒谎。但当你随手划一道颜色时，你的手指不会撒谎。

颜色、速度、力度——这些都是情绪发生的形状，不是被加工后的翻译。

**核心洞察三：同频的陌生人，比熟人更懂你**

熟人社交（朋友圈）有社交压力——你不敢发真实感受，怕被judge。但陌生人之间，反而更容易产生共鸣。

当你看到一个人画的画，颜色和笔触跟你很像——你会产生一种奇妙的感觉："原来有人和我一样。"

你们不需要认识对方，不需要聊天，只需要知道对方存在。

**核心洞察四："画"字的压力太大了**

大多数人听到"画画"两个字，第一反应是"我不会画""我画得丑"。

所以我们不说"画画"，我们说"涂"——随便涂，怎么涂都对。

没有对错，没有好坏，没有评价。

### 1.3 我们想做什么

基于以上洞察，我们决定做这样一款产品：

> **一个通过音乐和手指涂抹来记录情绪，并让同频陌生人产生共鸣的社交平台。**

我们不要求用户画得好，不分析用户的情绪，不评判用户的笔触。

我们只做三件事：

1. 让音乐驱动颜色和粒子，成为用户的画布底色
2. 让用户自由涂抹，留下属于自己的痕迹
3. 让"画得跟你很像的人"被发现、被连接

**品牌定位：** 全球首个"音乐情绪可视化社交平台"

**品牌名：Tone-Shift（音变）**

- Tone = 音调、色调、语气
- Shift = 转变、偏移、漂移

**Logo：** 波浪线（~）穿过一个圆点，代表音调的偏移、情绪的流动。

### 1.4 一句话定义

> **Tone-Shift：随便涂，有人听。**

## 第二部分：市场背景与机会分析

### 2.1 行业背景

在线音乐行业正在经历一场变革。

**市场规模：**

- 中国在线音乐用户规模：约7.5亿
- 全球在线音乐用户规模：超过10亿
- 中国在线音乐市场规模：约400-500亿元/年

**行业趋势：**

过去十年，音乐App的核心竞争是"版权"和"推荐算法"。但这两个维度已经接近饱和——主流音乐平台（QQ音乐、网易云、汽水音乐）在歌曲数量和推荐精准度上差距越来越小。

新的竞争方向正在形成：**音乐社交**。

汽水音乐凭借"短视频+音乐"差异化路径，截至2025年9月月活已达1.2亿，进入行业第一梯队。但其模式本质仍是算法推荐，用户角色依然是被动的"听者"，而非主动的"创作者"。

网易云音乐以"评论区文化"著称，试图营造用户互动氛围，但表达方式仅限于文字，缺乏更直观的情绪载体。

### 2.2 市场空白

我们分析了主流音乐产品的功能，发现一个共同的空白：

| 功能维度 | 现有产品提供 | 缺失什么 |
| :--- | :--- | :--- |
| 听 | 海量曲库、推荐算法 | — |
| 发现 | 榜单、歌单、推荐 | — |
| 表达 | 文字评论、分享歌名 | 无法用非语言方式表达感受 |
| 记录 | 播放历史、收藏歌单 | 无法记录"当时的感受" |
| 社交 | 关注、私信、评论区互动 | 无法基于"情绪相似性"建立连接 |
| 创作 | 用户歌单、Mlog（部分平台） | 创作门槛高，需要文字或视频能力 |

**具体来说：**

- 用户听完一首有感触的歌，只能写文字评论或分享歌名
- 播放记录是冷冰冰的数据，"那年今日你听了这首歌"没有情感厚度
- 表达情绪需要文笔、需要勇气、需要组织语言
- "我懂你"只能用文字说，缺少更直接的情绪连接方式

### 2.3 我们的差异化机会

| 维度 | 现有产品 | Tone-Shift |
| :--- | :--- | :--- |
| 核心行为 | 听 | 听 -> 涂 -> 共鸣 |
| 用户角色 | 被动听众 | 主动创作者 |
| 产出物 | 播放记录、文字评论 | 独一无二的情绪痕迹 |
| 社交纽带 | 歌、评论、歌单 | "画得跟你很像的人" |
| 表达方式 | 语言 | 颜色 + 痕迹（非语言） |
| 创作门槛 | 高（要会写/会拍/会唱） | 极低（随便涂） |
| 留存机制 | 歌单/推荐 | 打卡 + 周报 + 情绪画像 |

### 2.4 为什么这个机会现在出现

**技术条件成熟：**

- 手机触摸屏精度足以捕捉手指压力、速度和轨迹
- 实时音频频谱分析在移动端已经非常成熟（GetSpectrumData等API）
- 粒子渲染在移动设备上可以达到60fps流畅体验
- Flutter等跨平台框架降低了开发成本

**用户心理需求变化：**

- Z世代更倾向于"非语言表达"（表情包、Emoji、涂鸦已经证明了这一点）
- 人们对"被算法分析"越来越警惕，更渴望"被看见但不被定义"的空间
- 熟人社交的疲劳感在上升，陌生人"同频连接"的需求在增加

## 第四部分：产品功能详解

### 4.1 产品架构总览

Tone-Shift的产品体系由两大模块组成：单人模式和多人互动模式。

**单人模式**是用户"与自己对话"的空间，包含三种核心玩法：

- 自由听画（核心模式，含打卡分支）
- 记忆考古
- 传声链

**多人互动模式**是用户"与他人对话"的空间，包含一种核心玩法：

- 音画传声筒

两种模式共享底层的"音乐->视觉"转化引擎，但用户场景和社交深度不同。

### 4.2 单人模式一：自由听画（核心模式）

这是整个产品的基础和入口，也是大多数用户第一次打开App时的体验。

**完整流程：**

| 步骤 | 用户做什么 | 系统做什么 | 产出 |
| :--- | :--- | :--- | :--- |
| 1. 选歌 | 从音乐平台选择一首歌 | 连接音乐平台API | 歌曲准备播放 |
| 2. 沉浸 | 闭眼听歌30-60秒 | 提取音频频谱数据 | 画布"底色"生成中 |
| 3. 涂抹 | 用手指在全屏画布上随意滑动 | 实时采集三种物理数据 | 粒子流随手指和音乐运动 |
| 4. 完成 | 输入标题、选择Public/Private | 保存画作到云端 | 画作进入时间线 |

**选歌来源：**

- 接入QQ音乐/网易云/Apple Music API
- 用户登录后可直接播放自己歌单中的歌曲
- 也可使用App内推荐的"每日一歌"

**沉浸听歌阶段的技术逻辑：**

系统在30-60秒内完成音频频谱分析，建立"这首歌的底色"：

| 音频维度 | 提取方式 | 视觉映射 |
| :--- | :--- | :--- |
| 低频（贝斯/鼓点，20-150Hz） | GetSpectrumData | 画布底层色块的**下沉深度** |
| 中频（人声/旋律，150-2000Hz） | GetSpectrumData | 画布中层线条的**流动方向** |
| 高频（镲/高音，2000-8000Hz） | GetSpectrumData | 画布上层光点的**闪烁频率** |

**核心交互：三种物理数据采集：**

| 物理数据 | 采集方式 | 视觉反馈 |
| :--- | :--- | :--- |
| 颜色选择 | 底部色盘 / 系统推荐色（基于歌曲情绪） | 粒子颜色随选择变化 |
| 手指压力 | 触摸API直接读取（Mac触控板/Apple Pencil支持压力感应） | 重按=粒子炸裂 / 轻按=粒子流淌 |
| 滑动速度 | 距离÷时间计算 | 快=轨迹拉长 / 慢=轨迹堆积 |

**压力感应的设备支持：**

| 设备 | 是否支持压力 | 说明 |
| :--- | :--- | :--- |
| MacBook触控板（2015年后） | ✅ | 支持Force Touch，pressure值0-1变化 |
| iPad + Apple Pencil | ✅ | 压力感应灵敏，适合精细创作 |
| iPhone触摸屏（3D Touch） | ✅ | 支持压力感应 |
| iPhone触摸屏（Haptic Touch） | ❌ | 不支持压力，使用速度模拟降级 |
| 普通鼠标 | ❌ | 使用移动速度模拟压力 |

### 4.3 自由听画的打卡分支

**为什么增加打卡机制：**

用户留存是社交产品最核心的挑战之一。"自由听画"模式虽然有很强的沉浸感，但用户可能会"想起来才用"，缺乏持续回来的动力。打卡机制通过"连续记录"的心理激励，让用户形成每日习惯。

**打卡机制设计：**

| 功能 | 说明 |
| :--- | :--- |
| 每日打卡 | 用户每天完成任意一幅画，当天打卡日期被点亮 |
| 连续记录 | 打卡日期连成一条线，可回看"我已连续画了X天" |
| 入口位置 | 自由听画模式下，左上角显示"连续打卡：X天" |
| 日历视图 | 点击后可查看完整的打卡日历（以月为单位） |

**打卡的心理机制：**

- 用户会为了"不断掉连续记录"而每天回来
- 连续7天、30天、100天时，系统自动生成"坚持徽章"
- 徽章可以保存，也可以选择是否分享

### 4.4 公开/隐私与社交连接

**完成画作后的选择：**

| 选项 | 说明 | 可见范围 |
| :--- | :--- | :--- |
| Public | 画作发布到公开广场 | 所有用户可见，可点赞/评论 |
| Private | 画作仅自己可见 | 仅用户本人 |

**公开画作的互动形式：**

每幅公开画作下方显示：

- 点赞数（"感同身受"）
- 评论数
- 收藏数

评论功能：

- 用户可以输入文字评论
- 可以快速画一笔作为"回声评论"——画出一个简单的颜色或形状作为回应

**"回声评论"的设计初衷：**

很多人在看到别人的情绪表达时，会觉得"我懂你"但不知道该怎么说。用一笔颜色来回应，比文字更直接、更诚实、更没有压力。

### 4.5 单人模式二：记忆考古

**这个模式解决什么问题：**

每个人都有一个经历：脑子里有一段旋律，知道那首歌对自己很重要，但死活想不起名字。

你哼给朋友听，朋友说"没听过"。你搜歌词，只记得一两个词，搜不到。那首歌像一块石头，一直压在你心里。

**完整流程：**

| 步骤 | 用户做什么 | 系统做什么 |
| :--- | :--- | :--- |
| 1. 画旋律轮廓 | 用手指画出印象中的旋律起伏（高音画上、低音画下、节奏快画密） | 记录画出的旋律形状 |
| 2. 选颜色和年代 | 选择对这首歌的"颜色印象"和大概年代 | 作为筛选条件 |
| 3. 写碎片信息 | 可选：写歌词片段、描述第一次听到的场景 | 辅助匹配 |
| 4. 系统匹配 | — | 给出候选歌曲列表 + 播放试听片段 |
| 5. 追问缩小范围 | 回答系统追问 | 不断缩小候选范围 |
| 6. 找到 / 生成近似 | 确认歌曲 / 或接受"记忆近似曲" | 保存成个人"音乐记忆卡" |

**"记忆近似曲"保底机制：**

如果系统确实找不到用户描述的歌，会基于用户提供的所有信息（旋律形状、颜色、年代、碎片文字），生成一段"记忆近似曲"——不是原歌，是AI生成的、可能接近用户记忆的音乐。

保证用户不会空手而归。

### 4.6 单人模式三：传声链

**这个模式解决什么问题：**

我们有时候会觉得"我理解这首歌的方式才是对的"。但事实是，同一首歌在不同人听来完全不同——而且每种理解都有它的道理。

这个模式让用户亲身体验"理解的漂移"，在娱乐中反思自己的认知局限。

**核心机制：**

用户和2-3个AI听友一起传歌猜歌。每个AI听友有不同"性格"，对同一首歌的理解方式完全不同。

**AI听友性格类型：**

| AI听友 | 性格特征 | 对同一首歌的理解方式 |
| :--- | :--- | :--- |
| 怀旧收集者 | 倾向于老歌和年代联想 | 听到《起风了》-> 联想到《光阴的故事》 |
| 理性乐评人 | 更关注节奏、风格和结构 | 分析"4/4拍，C大调，民谣结构" |
| 视觉系玩家 | 更容易根据颜色和画面理解 | 画出"一片被风吹乱的黄色落叶" |
| 荒诞派 | 产生搞笑但有趣的漂移 | "这首歌听起来像一只猫在追自己的尾巴" |
| 共情型听众 | 更关注歌词和情绪 | "这首歌让我想起那年夏天" |

**玩家操作流程：**

1. 用户选择自己的位置（第1个/中间/最后）
2. 选择2-3个AI听友
3. 选一首歌
4. 按顺序传歌：每人基于自己的理解猜歌、画歌、描述
5. 最后观看整条链的漂移——"原曲"到"第3个AI的理解"之间的变化路径
6. 系统自动生成"漂移总结"

**核心高潮：**

用户看到同一首歌从原曲到最后一个AI的理解已经面目全非——他会笑、会感叹、会反思："原来我以为的'这首歌的意思'，也只是我的版本而已。"

### 4.7 多人互动模式：音画传声筒

**这个模式解决什么问题：**

多人游戏是社交产品的核心驱动力。"音画传声筒"结合了猜歌、你画我猜、音乐创作、社交分享四种体验，并且天然具有病毒传播属性。

**一句话说清：**

一首歌，经过"文字->绘画->文字->绘画"的多轮接力，最后AI把所有人的理解合成一首全新的共创音乐。

**完整流程：**

| 轮次 | 谁做 | 做什么 | 输出什么 | 时间限制 |
| :--- | :--- | :--- | :--- | :--- |
| 第1轮 | A（发起人） | 听一首歌的15秒片段 | 用3个字概括这首歌 | 15秒听歌+10秒写词 |
| 第2轮 | B | 看到A写的3个字 | 只能画画表达（不能出现文字） | 60秒绘画 |
| 第3轮 | C | 看到B画的画 | 用3个字概括 | 20秒思考+10秒写词 |
| 第4轮 | D | 看到C写的3个字 | 只能画画表达 | 60秒绘画 |
| 第5轮 | AI+所有人 | AI同时做两件事 | 揭晓原歌名 + 生成30秒共创音乐 | — |

**关于"三字限制"的设计思考：**

用户可能会质疑："为什么不能直接写歌名？"

这个设计的核心在于：我们不是在玩"猜歌名"游戏，而是在玩"感觉传递"游戏。

如果A直接写歌名，那B和C就没有任何"理解空间"了——整个游戏会变成一次简单的信息传递，而不是一次有趣的"漂移"实验。

用3个字概括一首歌，意味着每个人必须做出选择：舍弃哪些元素、保留哪些元素。这个选择本身就暴露了他对这首歌的"个人理解"。

比如《好想好想你》：

- 有人选"夏天、风、等待"（怀念）
- 有人选"暗红、雨、沉默"（悲伤）
- 有人选"阳光、操场、背影"（青春）

这三个答案都对，但每个答案都不一样——这才是游戏的核心乐趣。

**AI的三段式生成（共创音乐高潮）：**

| 输入内容 | 变成什么音轨 | 技术说明 |
| :--- | :--- | :--- |
| A的3个字 | 一段人声采样片段 | 根据3个字的情绪，从素材库中匹配对应的人声吟唱 |
| B的画 | 一层旋律 | 提取画的主色调和形状，映射到乐器音色和旋律走向 |
| C的3个字 | 一段人声采样片段 | 与A的处理方式相同 |
| D的画 | 一层和弦/节奏 | 提取画的密度和饱和度，映射到鼓点和弦 |
| 原歌 | 一个隐藏的"彩蛋采样" | 原歌1秒片段被变调/倒放后藏在背景层中 |

**最终效果：** 用户听到的是"A的3个字变成的旋律+B的画变成的乐器+C的3个字变成的人声+D的画变成的节奏"——每一层都对应着这个小组里某个人的贡献。

### 4.8 AI报告系统（会员增值功能）

**功能定义：**

根据用户每周/每月/每年的所有画作数据，自动生成一份"情绪画像报告"。只有会员可查看完整报告，免费用户只可见每日一句心情小语。

**报告包含的数据维度：**

| 维度 | 数据来源 | 示例输出 |
| :--- | :--- | :--- |
| 主色调趋势 | 本周所有画作的颜色统计 | "你这周的主色调是蓝灰色，比上周冷了15%" |
| 笔触活跃度 | 滑动速度、压力平均值 | "你这周画得比上周更重" |
| 创作频率 | 打卡天数、每日画作数量 | "你这周画了6天，最高产的是周三" |
| 最活跃时段 | 创作时间统计 | "你习惯在晚上10-11点画画" |
| 最常听的歌/类型 | 关联的音乐数据 | "你这周最常画的是周杰伦的歌" |

**人格标签生成（仅供娱乐，非心理学分析）：**

| 人格类型 | 特征描述 |
| :--- | :--- |
| 深海型 | 偏爱冷色调、低频音乐、笔触沉稳 |
| 焰火型 | 偏爱暖色调、快节奏、笔触跳跃 |
| 晨雾型 | 偏爱柔和色、中速、笔触轻盈 |
| 暗涌型 | 颜色反差大、笔触忽轻忽重 |
| 留白型 | 画作稀疏、颜色单一 |

**三份报告的具体内容：**

| 报告 | 推送时间 | 包含内容 |
| :--- | :--- | :--- |
| 周报 | 每周一 | 本周主色调趋势、创作频率、最常听歌曲、人格标签、一句话总结 |
| 月报 | 每月1日 | 颜色分布图、创作趋势线、Top3歌曲、人格标签、与上月对比 |
| 年报 | 每年12月31日 | 全年颜色总览、365天打卡热力图、Top10歌曲、人格演变轨迹、年度关键词、AI年度情绪信、可分享的年度情绪海报 |

## 第五部分：AI在产品中的角色

### 5.1 AI做什么，不做什么

这是一个非常关键的定位问题。用户最抗拒的就是"被AI分析情绪"——因为只有他自己知道那一刻他真正的感受是什么。

所以在Tone-Shift中，AI的边界非常清晰：

| AI做的事（清晰明确） | AI不做的事（坚决避免） |
| :--- | :--- |
| 分析**音乐本身**（频谱数据->色块/线条/光点） | 不分析**用户情绪**（不贴"你很悲伤"的标签） |
| 生成**情绪色票**（5个主色的数学统计） | 不判断"画得好不好" |
| 生成**情绪周报/月报/年报**（数据趋势呈现） | 不美化用户的画（已删除AI改画功能） |
| 生成**记忆考古**的候选歌曲 | 不替用户下结论 |

### 5.2 AI在各模式中的具体作用

| 模式 | AI的角色 | 具体任务 |
| :--- | :--- | :--- |
| 自由听画 | 底色生成器 | 分析音乐频谱，映射为画布底层的色块/线条/光点 |
| 自由听画 | 色票生成器 | 提取画作中的5个主色，生成标准色票 |
| 记忆考古 | 音乐侦探 | 根据旋律形状/颜色/年代/碎片文字匹配候选歌曲 |
| 记忆考古 | 近似曲生成器 | 找不到原曲时生成"记忆近似曲" |
| 传声链 | 听友扮演者 | 模拟5种不同性格的AI听友，产生不同的理解漂移 |
| 音画传声筒 | 共创音乐合成器 | 把每轮内容合成为30秒共创音乐 |
| 音画传声筒 | 漂移分析器 | 分析漂移链条，生成"漂移总结" |
| AI报告 | 数据叙事者 | 把颜色/速度/频率数据变成有温度的周报/月报/年报 |

### 5.3 AI技术的具体实现

**音频频谱分析：**

采用Web Audio API或原生音频API提取频谱数据，不依赖任何第三方AI服务。

**色调映射：**

颜色映射基于预设规则（如：低频->暖色下沉、中频->冷色流动），不需要训练模型。

**候选歌曲匹配（记忆考古）：**

基于旋律形状相似度+标签匹配（颜色、年代、歌词关键词），采用向量检索+规则匹配。技术方案成熟，无大模型依赖。

**AI听友（传声链）：**

每个AI听友基于不同的规则引擎产生不同的"理解漂移"（如：怀旧型匹配老歌库、乐评型分析曲风结构），而非自由生成，确保行为可预测、可控制。

**音乐素材库匹配（音画传声筒共创音乐）：**

从预设的音乐素材库（人声吟唱片段、乐器采样、节奏型）中根据情绪标签匹配，再叠加合成，而非让AI自由创作音乐。

### 6.2 同频匹配算法（核心社交特色）

**匹配维度：**

| 维度 | 数据来源 | 权重 |
| :--- | :--- | :--- |
| 颜色分布相似度 | 用户所有公开画作的主色统计 | 40% |
| 笔触特征相似度 | 速度/压力平均值 | 30% |
| 常听歌曲类型相似度 | 关联的音乐平台数据 | 30% |

**匹配逻辑：**

不看脸、不看身份、不看年龄性别——只看"你留下的痕迹"是否相似。

**为什么这样设计：**

传统的社交匹配基于"相似背景"（年龄、职业、兴趣爱好），但Tone-Shift认为情绪层面的相似比背景层面的相似更重要。

两个人可能年龄相差20岁、生活在不同城市，但他们对同一首歌的"颜色感受"可能完全相同——这种连接更有意义。

### 9.1 技术架构总览

| 层级 | 技术选型 | 说明 |
| :--- | :--- | :--- |
| 前端 | Flutter | 跨平台，一套代码适配iOS和Android |
| 音频处理 | 原生Audio API / Unity音频引擎 | 实时频谱分析（GetSpectrumData） |
| 图形渲染 | Metal（iOS）/ Vulkan（Android） | 高效粒子渲染，支持60fps |
| 后端 | Node.js + PostgreSQL | 用户系统、画作存储、社交数据 |
| 缓存 | Redis | 会话缓存、热点数据 |
| 云存储 | 阿里云OSS / 七牛云 | 画作图片存储、CDN加速 |
| AI匹配 | 协同过滤算法 | 基于颜色+笔触+音乐类型匹配 |

### 9.2 关键技术模块详解

**9.2.1 音频->视觉实时映射**

采用Unity AudioSource.GetSpectrumData或Web Audio API提取频谱数据：

```
频谱数据提取：
- FFT size: 256或512
- 频段划分：低频20-150Hz / 中频150-2000Hz / 高频2000-8000Hz
- 更新时间：每帧（约16ms）

映射规则：
- 低频能量 -> 色块Y轴位置（下沉深度）
- 中频能量 -> 粒子速度方向（流动）
- 高频能量 -> 粒子透明度（闪烁）
```

**9.2.2 压力感应交互**

| 设备类型 | 支持方案 | 降级方案 |
| :--- | :--- | :--- |
| MacBook触控板（2015+） | PointerEvent.pressure（0.0-1.0） | — |
| iPad + Apple Pencil | PointerEvent.pressure | — |
| iPhone（3D Touch） | PointerEvent.pressure | — |
| iPhone（Haptic Touch） | 不支持 | 使用滑动速度模拟压力 |
| 普通鼠标 | 不支持 | 使用移动速度模拟压力 |

**速度模拟压力的算法：**

- 记录最近5帧的位置数据
- 计算平均移动速度（像素/秒）
- 映射到0.0-1.0区间
- 速度高->模拟"重按"（粒子炸裂）
- 速度低->模拟"轻按"（粒子流淌）

**9.2.3 粒子系统性能优化**

| 优化策略 | 说明 |
| :--- | :--- |
| GPU Instancing | 批量渲染相同材质的粒子，减少Draw Call |
| 粒子数量控制 | 500-2000个，根据设备性能动态调整 |
| LOD分级 | 低端设备降低粒子质量和数量 |
| 对象池 | 复用粒子对象，避免频繁创建/销毁 |

**9.2.4 同频匹配算法（协同过滤）**

用户特征向量构建：

- 颜色偏好向量（5维）：RGB各通道的均值 + 饱和度均值 + 色相均值
- 笔触特征向量（3维）：速度均值、压力均值、停顿次数
- 音乐类型向量（10维）：10种主要音乐类型（摇滚/民谣/电子/说唱/古典/流行/爵士/R&B/金属/世界音乐）的播放占比

匹配算法：

- 计算用户之间的余弦相似度
- 每日更新，推送相似度Top3的用户
- 新用户有冷启动期：前3天基于音乐类型匹配

**9.2.5 数据隐私**

- 用户画作数据加密存储
- AI分析在用户设备本地完成（不上传云端）
- 用户可随时删除自己的画作和数据
- 公开/隐私设置由用户自主决定
